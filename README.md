# Практическая работа №5. PHP ООП: классы, конструкторы и модели предметной области

Дисциплина: «Технологии разработки программного обеспечения».

## Описание результата

PHP-приложение «Каталог товаров». Данные читаются из `products.json` и `categories.json`, превращаются в объекты `Product` и `Category`, а страница `public/index.php` показывает их карточками. Есть фильтр по категории, средняя цена выбранных товаров и состояния для пустого каталога и ошибок данных.

## Технологии

- PHP 8.x (проверено на встроенном сервере)
- HTML, CSS без фреймворков

## Требования к окружению

- PHP 8.0 или новее (`php -v`)
- Git

## Запуск

```bash
git clone <ссылка на репозиторий>
cd <папка репозитория>
php -S localhost:8000 -t public
```

Откройте в браузере `http://localhost:8000`.

## Структура проекта

```
data/
  dataset/       исходные данные: products.json, categories.json, class_requirements.csv
  example/       учебный пример из задания
public/
  index.php      точка входа, вывод HTML, обработка фильтра
  style.css      оформление
src/
  models/        Product.php, Category.php
  services/      CatalogService.php
```

## Схема

```
products.json, categories.json
        │
        ▼
CatalogService  ──►  объекты Product и Category
        │
        ▼
    index.php   ──►  HTML-карточки 
```

- **Product, Category** описывают данные и поведение одного объекта. Проверяют свои данные в конструкторе. HTML не знают.
- **CatalogService** читает JSON, проверяет структуру, создаёт объекты, фильтрует по категории и считает среднюю цену.
- **index.php** принимает параметр фильтра, вызывает сервис и выводит результат. Всё, что связано с HTML, находится только здесь.

## Классы и методы

- `Product`: `getId`, `getName`, `getPrice`, `getCategoryId`, `isActive` и методы предметной области `formattedPrice`, `isAvailable`, `belongsToCategory`, `priceWithDiscount`.
- `Category`: `getId`, `getName`, `contains`.
- `CatalogService`: `loadProducts`, `loadCategories`, `filterByCategory`, `averagePrice`.

Поле `active` отсутствует в `class_requirements.csv`, но есть в `products.json`, поэтому добавлено в `Product`: оно определяет, доступен ли товар (`isAvailable`). Если поля нет в данных, товар считается активным.

После шага 4 в `Product` появились методы предметной области `formattedPrice`, `isAvailable`, `belongsToCategory` и `priceWithDiscount`, а не только геттеры.

## Обработка ошибок

- Конструкторы `Product` и `Category` бросают `InvalidArgumentException` при некорректных данных (пустое название, отрицательная цена, неположительный id).
- `CatalogService` бросает исключение, если файл не найден, JSON некорректен или в записи нет обязательного поля.
- `index.php` ловит эти исключения и показывает сообщение, не выводя PHP warnings. Некорректный параметр `category` игнорируется с предупреждением.

## Сценарий проверки

1. Откройте страницу: должно быть 12 карточек, у товаров 5 и 10 плашка «недоступен».
2. Выберите категорию «Оборудование»: 4 товара, средняя цена `1 055,25 ₽`.
3. Откройте `/?category=abc`: предупреждение, каталог показан целиком.
4. Временно удалите поле `price` у одного товара в `products.json`: страница покажет сообщение об ошибке данных.

## Почему ручные `require_once` неудобны при росте проекта

Каждый новый класс приходится подключать вручную в каждом файле, где он нужен. Легко забыть подключение или нарушить порядок, а при переименовании или переносе файла нужно править пути по всему коду. В больших проектах для этого используют автозагрузку классов.
